5 Model Router — Smart Swaps + a Rescue Ladder

Two levels: proactive swaps based on content type (before generation), and reactive fallback when the stream fails.

A) Proactive swaps based on content

📹 Unsupported video/audio — or oversized video?
Media modelX-Media-Mode
📚 Textbook chunks from RAG?
Textbook-QA modelX-Study-Mode
🖼️ Message carries images?
Vision modelX-Vision-Mode

B) Fallback ladder on stream failure (up to 3 attempts)

Attempt 1 — the selected model
✖ Failed → report to modelRouter
Attempt 2 — first model in the fallback chainUI notified via X-Model-Fallback
✖ Failed → wait 500ms×2
Attempt 3 — second fallback model
✖ All attempts failed — Arabic apology message + error chunk in the stream

Reference: chat.pipeline.ts steps 1.5 / 5b / 5c (proactive) • response-generator.service.ts:112-228 (reactive)

6 Where Your System Sits on the Known Pattern Map

Compared against the standard agent-pattern taxonomy — so you know exactly where you stand.

🚚 Routing✔ have it

Intent classifier + tool router + model router — every request gets a path tailored to its type

⛓️ Prompt Chaining (fixed chain)✔ have it

Phases A→E: each step prepares inputs for the next in a locked, pre-defined order

🪞 Evaluator-Optimizer◐ optional

The generator+critic pattern — implemented in code but off by default (MULTI_AGENT_ENABLED)

🔧 Tool-Calling Agent✔ capped

A real ReAct loop but bounded — 15 steps max, against a pre-filtered tool list

🎺 Orchestrator-Workers✖ not present

No lead agent fanning tasks out to parallel sub-agents — everything is sequential

🤖 Autonomous Agent✖ not present

No uncapped open loop, no self-directed planning — and that's a sound choice for a production app

Bottom line: Intent-Routed Pipeline + Bounded ReAct Loop (+ optional Critic) — balancing predictability and known cost, with model flexibility only at generation time
