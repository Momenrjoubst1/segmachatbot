6 The Chatbot on the Pattern Map — Sigma vs Claude.ai vs Claude Code

Same taxonomy as the other two pages — now all three systems side by side.

⛓️ Prompt Chaining✖ not fixed

no published pre-coded chain; context assembly is feature-driven, not a hardcoded step list

🚚 Routing✔

"needs tools?" split at every message (Map 3) • manual model picker (Opus/Sonnet/Haiku) • effort tiers in Research

🔀 Parallelization✔ in Research

3–5 subagents simultaneously, each with 3+ parallel tool calls — the documented 90% time cut

🎺 Orchestrator–Workers✔ in Research

lead agent + parallel workers + synthesis + CitationAgent — Anthropic's own published architecture

🪞 Evaluator–Optimizer◐ one pass

CitationAgent is a verifier pass after generation — but there's no documented iterate-until-good critic loop

🤖 Autonomous Agent◐ bounded

the hidden loop decides its own tool use, but consumer chat shows no open-ended autonomy — that's reserved for Research and Claude Code

🎓 Sigma (yours)

  • Fixed 11-step pipeline, deterministic rails
  • Bounded ReAct — 15 steps, intent-filtered tools
  • Context built in pipeline steps (courses, RAG, memory)
  • Every mechanism visible in your own code

💬 Claude.ai (chatbot)

  • Calm surface; machinery invisible by design
  • Hidden tool loop, effort scaled to the query
  • Context via product features (memory, projects, skills)
  • Full orchestrator-workers — but only in Research mode

⌨️ Claude Code

  • The loop is the whole program — no fixed chain
  • Unbounded steps, exits on verified evidence
  • Subagents on demand, any task, any time
  • Human gates wired in (permissions, plan mode)

The gradient to remember: autonomy grows left → right (Sigma's rails → chatbot's hidden loop → Code's open loop), and so does cost & unpredictability. Anthropic's own advice — simplest thing that works — is exactly the logic that puts your Sigma pipeline where it is.
