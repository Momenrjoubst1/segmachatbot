How Claude (Claude Code) actually runs a task — same lens we used for your Sigma pipeline, grounded in Anthropic's published docs & blog

1 The Big Picture — There Is No Pipeline

This is the deepest contrast with Sigma: Sigma wraps a small agent inside a fixed step chain. Claude is the loop all the way down — the model directs its own path, nothing is pre-coded.

👤 Human gives a goal
a task, a bug, a feature — in natural language
🔁 The agentic loop — "LLMs using tools based on environmental feedback, in a loop"
Gather context Take action Verify work …repeat until done
🚧 permission prompt before risky actions 🪜 plan mode = read-only until approved
✅ Done when verified — not when a step counter runs out

Anthropic's own distinction: workflows = "orchestrated through predefined code paths" (that's Sigma) vs agents = "LLMs dynamically direct their own processes and tool usage" (that's Claude). Source: Building Effective Agents, anthropic.com/research/building-effective-agents

4 Orchestrator–Workers — The Subagent System

Claude's signature second pattern: a lead agent decomposes the task at runtime and fans work out to subagents — each in its own context window.

🧭 Lead agentplans, delegates via the Agent tool, merges results — keeps its own context
🔎 Exploreread-only search agent
📋 Planplan-mode research agent
🛠️ General-purpose+ your custom .claude/agents/
each subagent: own context window • own tools • own permissions
📩 Summaries only flow back"returns only the summary" — noisy transcripts never flood the main context
subtasks chosen at runtime — the blog's own example: "coding changes across an unknown number of files" nesting ≤ 3 layers ≤ 20 concurrent spawns background results arrive as notifications forks inherit the full conversation

6 Claude on Anthropic's Own Pattern Map — and Next to Sigma

The six patterns come from Anthropic's Building Effective Agents — so Claude Code is graded against its own company's taxonomy.

⛓️ Prompt Chaining◐ within turns

decompose → step → step, with gates. Claude does this inside the loop when useful — but nothing is fixed in code

🚚 Routing✔

difficulty → model, task → subagent (matched against each subagent's description), skill selection

🔀 Parallelization✔

sectioning via fan-out subagents running simultaneously; voting is available and used for confidence-critical checks

🎺 Orchestrator–Workers★ core

the lead-agent + subagent architecture — dynamic decomposition, results merged back. Claude Code's signature

🪞 Evaluator–Optimizer◐ loop form

the verify→fix cycle iterates against test output & criteria — but the same model plays both roles, no separate critic

🤖 Autonomous Agent★ the design

"LLMs dynamically direct their own processes and tool usage" in a loop with guardrails — the exact definition Claude Code implements

🎓 Sigma (yours)

  • Fixed pipeline — 11 pre-coded steps, deterministic rails
  • Bounded ReAct — tools capped at 15 steps, statically filtered by intent
  • Model swaps by message content (media / textbook / vision)
  • Critic optional, off by default
  • Optimized for: predictability, known cost, TPM safety

🤖 Claude (Code)

  • Open loop — model directs its own path, no pre-coded chain
  • Unbounded steps — exits on verified evidence, caps only on subagents
  • Model routes by task difficulty; subagents isolate context
  • Human gates wired in — permissions & plan mode
  • Optimized for: flexibility on open-ended problems

And Anthropic's own advice cuts both ways: "find the simplest solution first" — workflows give predictability for well-defined tasks; agents earn their cost only when the path can't be hardcoded. Your Sigma pipeline is the textbook workflow-plus-bounded-loop for a chat product; Claude Code is the textbook autonomous agent for coding.
